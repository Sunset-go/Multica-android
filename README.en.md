A standalone Expo / React Native client for [Multica](https://github.com/multica-ai/multica), extracted from the Multica monorepo. This repository bundles the mobile app (`apps/mobile/`) together with its shared business logic package `@multica/core`, organized as a self-contained pnpm workspace.

> 中文版: [README.md](./README.md)

## 📦 Download APK

Latest releases are available in [Releases](https://github.com/Sunset-go/Multica-android/releases), with two variants:

- `multica-app-v<version>.apk` — universal (all ABIs, larger, compatible with older devices)
- `multica-app-v<version>-arm64.apk` — arm64-only (smaller, recommended for modern phones)

## Repository layout

- `apps/mobile/` — Expo app (iOS + Android), the source of Android APK builds.
- `packages/core/` — shared business logic, API clients, type definitions, pure utilities (runtime dependency).
- `packages/tsconfig/`, `packages/eslint-config/` — workspace toolchain configs consumed by `@multica/core`.

## Prerequisites

- Node.js + pnpm 10 (`packageManager: pnpm@10.28.2`)
- iOS requires Xcode; Android requires the Android SDK
- See `apps/mobile/README.md` for full build / install instructions

## Install

```bash
pnpm install
```

`.env.staging` and `.env.production` are committed (public URLs). For a local backend, copy `apps/mobile/.env.example` to `apps/mobile/.env.development.local` and set `EXPO_PUBLIC_API_URL` to your machine's LAN IP.

## Common scripts

All commands run from the repo root and delegate to `apps/mobile/`:

| Command | Description |
|---|---|
| `pnpm dev:mobile` | Start Metro only (local backend) |
| `pnpm dev:mobile:staging` | Start Metro only (staging backend) |
| `pnpm dev:mobile:prod` | Start Metro only (production backend) |
| `pnpm ios:mobile` | iOS simulator rebuild + install (local) |
| `pnpm ios:mobile:staging` | iOS simulator rebuild + install (staging) |
| `pnpm ios:mobile:prod` | iOS simulator rebuild + install (production) |
| `pnpm ios:mobile:device` | USB iPhone full rebuild + install (local) |
| `pnpm ios:mobile:device:staging` | USB iPhone full rebuild + install (staging) |
| `pnpm ios:mobile:device:prod` | USB iPhone full rebuild + install (production) |
| `pnpm ios:mobile:device:prod:release` | USB iPhone Release build + install (production) |
| `pnpm typecheck` | TypeScript check (mobile) |
| `pnpm lint` | ESLint (mobile) |
| `pnpm test` | Unit tests (mobile) |

> Android: the `android/` native project is generated by Expo prebuild (gitignored). Run `pnpm exec expo prebuild --platform android` (or use EAS Build) to regenerate, then build the APK via Gradle — the artifact matches what the source workspace produces.

## Android Release APK

Inside `apps/mobile/android` (after prebuild):

```bash
ANDROID_HOME=/path/to/android-sdk ./gradlew assembleRelease -PreactNativeArchitectures=arm64-v8a
```

Output: `apps/mobile/android/app/build/outputs/apk/release/app-release.apk` (bundle ID `ai.multica.mobile`, version `0.2.7`).

## GitHub Actions release flow

Tag pushes matching `v*.*.*` trigger [`.github/workflows/android-release.yml`](.github/workflows/android-release.yml):

1. Set version from the tag (or a `workflow_dispatch` input)
2. Install pnpm, run `pnpm install`
3. `expo prebuild --platform android`
4. Matrix build two APKs (`universal` + `arm64-v8a`) in parallel
5. `softprops/action-gh-release@v2` uploads both APKs to the GitHub Release

The workflow also supports `workflow_dispatch` with a `version` input for manual builds without tagging.
